# 验证口径

| 阶段 | 检查什么 | 不能证明什么 |
|---|---|---|
| 结构检查 | Schema、ID、路径、数量、引用、脱敏、生成一致性 | 服务在线、授权成功 |
| 配置适配 | Codex TOML、Claude/Cherry JSON 解析与字段规则 | 客户端实际连接成功 |
| 原生插件检查 | 市场添加、安装、启用回读 | 模型会话会调用工具 |
| 目录协议检查 | SDK 与安装副本握手、工具发现、检索和导出 | 下游业务工具可用 |
| 远程协议检查 | initialize + tools/list、分页、超时、认证状态 | 业务正确性、账号权限、费用 |
| 业务验证 | 本次未进行 | 全部业务结论保持未验证 |

`reports/verification.json` 记录带时间和范围的真实观测；重试保留历史。`catalog_get` 返回 `latest_protocol_check`，不会把 HTTP 200、401、存在地址或已安装偷换成 MCP 协议通过。

当前四个指定条目在本机解析为非公开代理映射地址，已记录 `skipped / network-policy-blocked`。这是本机检查条件不足，不能表示远端服务失败。未放宽地址规则，也未修改用户网络。可在使用公开 DNS 的环境中显式重新运行 `scripts/probe.py`。

探测器不读取 WorkBuddy 账号/凭据，不接受任意本地命令，不跟随重定向；检查 HTTPS URL、DNS 地址和 SSE 返回的请求目标，只执行协议初始化及工具目录查询。它基于 URL/DNS 的保守应用层检查，不能替代网络层隔离；不建议把它部署成接收任意公众 URL 的代理服务。

CI 离线验证使用 SDK 模拟运输响应和真实本地 stdio 服务，不把不可控网络探测设为日常构建条件。需要认证的服务应由使用者在自己的客户端验证；不要把令牌放进公开 PR 或报告。
